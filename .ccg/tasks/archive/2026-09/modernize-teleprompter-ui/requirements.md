# 現代化提詞器 UI

- 使用者需求：將現有 UI 重製得更現代。
- 使用者補充：移動端才是最重要的，必須以手機使用優先。
- 使用者最新補充：優先做簡體中文。介面語言、示範文稿、提示及新文件以簡體中文為主，HTML lang 使用 zh-CN。
- 手機採用文稿／預覽／設定三個切換面板，開始按鈕固定底部並避開安全區；檢查窄螢幕、橫向、觸控與虛擬鍵盤。桌面才展開雙欄。
- 複雜度 M、風險 medium、領域 frontend；維持無建置步驟的靜態網站。
- 以淺色、清晰留白的編輯工作台與深色提詞預覽形成層級；提供桌面雙欄及行動裝置單欄配置。
- 保留現有 savedText 文稿快取相容性、六種字體、字級、速度、顏色、參考線、鏡像、計時器、倒數、全螢幕、拖曳、鍵盤及手柄操作；介面改為簡體中文。
- 編輯時即時更新文字統計及預览，控制元件具明確標籤、鍵盤焦點與可存取名稱。
- 本地文稿編輯與設定不能因 localStorage、Fullscreen 或 Wake Lock API 不可用而中斷。
- 預計產品檔案範圍：index.html、styles.css、app.js、manifest.json（視需要同步外觀與修正現有圖示路徑）；只在需要時更新 README 的使用說明。
- 不引入前端框架、後端、帳戶或遠端文稿儲存。
- 驗收：桌面與手機視覺檢查；瀏覽器驗證編輯、儲存、預覽、設定、倒數、播放、暫停、退出、鏡像、快捷鍵和重複啟動。
- 本專案開始時沒有 .ccg/spec 目錄，git 工作目錄乾淨。
- 按專案工作流，實作前雙路並行分析、實作後雙路並行審查，完成後歸檔並提交本次任務記錄。

## 分析結論

- 已平行呼叫指定 wrapper 的兩個 Claude 分析工作；兩者均 exit 1、無報告輸出。錯誤保留於 analysis/*.log，不將其列為成功分析。已向使用者說明，主代理完成本地程式檢查並持續實作。
- 現有程式的全域快捷鍵在編輯狀態仍會觸發；倒數與全螢幕退出的清理有競態；Wake Lock 未釋放。用清楚的 editor/countdown/playing/paused/finished 狀態處理新介面，保留既有功能。
- 將內嵌样式與混淆的互動腳本分成 styles.css 與 app.js，維持直接靜態開啟，不加入建置或框架。
- 預覽只鏡像文稿，不鏡像操作按鈕。讀稿區用 Pointer Events 共用滑鼠／觸控行為。
- 保留 localStorage 的 savedText 鍵與使用者故意清空的空字串；新的設定獨立儲存且需驗證型別、範圍。
- 圖示採本地 SVG，字體採系統字體備援，不依賴外部 UI 或字體服務。
